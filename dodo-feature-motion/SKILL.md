# Моушен про фичу — язык шоурилов Dodo

Ролик собирается кодом: HTML + GSAP на одном таймлайне, покадровый рендер через Playwright, сборка в MP4 через ffmpeg с настоящим motion blur. Правки точечные: «кнопку на 3 кадра раньше» — это одна строка.

Язык замерен покадрово на шоурилах **[Dodo 25–26](https://www.youtube.com/watch?v=SqheEG1VJ5A)** (90 с) и **[Dodo 26–27](https://www.youtube.com/watch?v=xVQIosadb0A)** (60 с), **Dodo_Full** (86 с, 1:1), **Genshin** (22 с), **«Новая главная»** и внешнем бенчмарке **Airbnb** (60 с, 9:16; у него берём только механику, цвет и бренд не берём). Правила качества и процесса проверены на ролике [«Редизайн профиля»](https://youtu.be/NEnV7mokLE4) (60 с, 4K, с музыкой).

## 0. Два закона (если запомнить только это)

1. **Один дубль.** В шоуриле 25–26 на 90 с всего 2 жёсткие склейки, в 26–27 на 60 с — 3. Всё остальное — переходы, после которых зритель не теряет, куда смотреть. Жёсткая склейка допустима не чаще одного раза за 30 с, только на бит и только между мирами (3D-сцена ↔ UI).
2. **Ничего не стоит, всё отвечает.** Удерживаемый объект дышит. У иконки есть характер: вилка с ножом покачиваются, курьер шагает, у коробки открывается крышка. Действие в UI меняет весь кадр: тоггл перекрашивает фон, нажатие выпускает лучи, частицы, конфетти.

## 1. Бриф (одним сообщением, только то, чего нет в запросе)

| Что | Зачем | Дефолт |
|---|---|---|
| **Формат** | **спрашивать всегда** | — : 16:9 3840×2160 / 1:1 2160 / 9:16 2160×3840 / 4:5 |

| **Финал/логотип** | | пилюля + заголовок акцентным шрифтом; логотип только файлом от пользователя |

**Figma — плотность пикселей решает качество.** Финал всегда в 4K (`--scale 2`), а телефон в кадре обычно увеличен ×1,1–1,55. Значит, на экране 1 pt макета = 2,2–3,1 px. Правило: **каждый растровый слой экспортируется с запасом ≥ 1× к своему максимальному экранному размеру в 4K**:
- экраны, шиты, длинные ленты, крупные фото — **×4**;
- мелкие элементы, которые наезжают крупно (аватар, иконка героя, пицца) — **×6**;
- видеосеквенции (стрим, футаж) — **в исходном разрешении**, без даунскейла (кроп — да, ресайз — нет).
2x-ассеты + 1080p-рендер дают мыло и «пиксели» на зумах — это главная причина претензий к качеству. Перед финалом обязательно прогнать `node kit/density.cjs work/scene.html` (§7.2).

**Если figma.com недоступен по сети** (curl по ссылке ассета даёт 403 от прокси — так бывает и в облаке, и на компьютере пользователя): выгружай через `use_figma` — `await node.screenshot({scale:4})` возвращает PNG прямо в ответ, файл сохраняется в `tool-results/mcp-Figma-blob-*.png`. Правила (выяснены на практике):
- **Лимит на размер одной картинки ~1 МБ PNG.** Если больше — она молча не приходит (ошибки нет). Плоский UI 1560×1700 px проходит; фото-контент (продукты, пицца, аватары-фото) — только полосами ~1560×260 px (390×65 pt при ×4). Режь на полосы через временный фрейм-клип и склеивай в Python.
- **Вызывать параллельно по одному скриншоту** (несколько `use_figma` в одном сообщении) — надёжнее, чем 4–5 скриншотов в цикле одного вызова: в цикле часто доходит только первый.
- Нода должна быть **на текущей странице**: `let p=n; while(p.type!=='PAGE') p=p.parent; await figma.setCurrentPageAsync(p)`. Иначе скриншот молча пустой.
- RECTANGLE с картинкой не снимается напрямую — клонируй во временный фрейм того же размера (`fills=[]`), сними фрейм, `remove()`.
- Полоса экрана: `f=createFrame(); f.resize(390,H); f.clipsContent=true; f.fills=[]; c=src.clone(); f.appendChild(c); c.y=-y0; c.resize(390, полная_высота)`; скрыть ненужные слои у клона по индексу детей исходника; `screenshot` → `f.remove()`.
- `exportAsync` + base64 в `return` не работает: лимит ответа 20 КБ.
- Чтобы снять экран **без** анимируемых слоёв: `clone()` фрейма → скрыть слои → `screenshot()` → `remove()` клона в том же вызове.
- Проверь альфу: аватары и 3D часто лежат VIDEO-заливкой с фоном — ищи ту же картинку IMAGE-заливкой. Поиск всех картинок с исходным размером: `findAll(n=>n.fills?.some(f=>f.type==='IMAGE'))` + `figma.getImageByHash(h).getSizeAsync()`.
- Шиты и карточки экспортируются с тенью — обрежь по непрозрачной области (alpha ≥ 250) и ставь свою CSS-тень. Белые подложки у PNG снимай color-to-alpha, а не оставляй «белую плашку».
- Текст на баблах и подписях, которые меняют ширину, — верстай HTML-текстом, а не растягивай PNG.
- После выгрузки разложи файлы по понятным именам (`sheet_help.png`, `chip_orders.png`, `avatar_anna.png`); сцена берёт пропорции из реальных размеров файлов (build-скрипт), поэтому более чёткий файл с теми же пропорциями — замена «на месте».
- Если картинку из макета не достать — апскейл Lanczos ×2 с премультиплицированной альфой (без ореолов) лучше, чем растяжение браузером; честно скажи пользователю, какие слои мягче.

## 2. Подача и ритм

### 2.1 Лестница масштаба

Каждая фича — прогулка по лестнице, а не показ экранов:

```
МИР            3D-город, глобус, пиццерия, трава      ← широкий контекст, эмоция
ОБЪЕКТ         иконка, 3D-предмет, эмодзи             ← символ фичи, крючок
КОМПОНЕНТ      пилюля, тоггл, карточка, поле, чип     ← здесь происходит действие
ЭКРАН          телефон целиком                        ← контекст, «где это в приложении»
УСТРОЙСТВО     часы, ТВ в пиццерии, второй телефон    ← фича за пределами экрана
```
- Переход сдвигает на **1–2 ступени**, никогда не на 3+.
- Внутри главы идём вниз (объект → компонент), потом вверх (компонент → экран), потом снова вниз к результату (наезд на сумму или статус). Это и даёт пульс.
- Пример из 26–27: город (мир) → оранжевая точка (объект) → иконка маршрута → пилюля «Маршрут» (компонент) → телефон (экран) → курьер на самокате (мир) → иконка курьера (объект) → строка адреса (компонент) → телефон.

### 2.2 Шаблон главы (5–7 с)

| t | Бит | Что происходит | Ступень |
|---|---|---|---|
| 0–1,0 | **Крючок** | объект-символ крупно, 20–35% кадра, камера близко (×2–2,5). Рождается из зерна. Сразу характерный жест | объект |
| 1,0–2,3 | **Изоляция** | контейнер вырастает из объекта (иконка → пилюля), камера отходит на ступень; текст печатается | компонент |
| 2,3–3,6 | **Действие** | снап-зум 4 кадра к месту действия → вдох 0,3–0,4 с → тап/тоггл/печать → **мир отвечает** (фон, лучи, частицы) | компонент |
| 3,6–5,0 | **Контекст** | шаг назад: телефон поднимается **за** компонентом, компонент садится в свой слот, UI дособирается стаггером 40–50 мс | экран |
| 5,0–6,5 | **Результат** | наезд на изменившееся (сумма, статус, бейдж): ролл цифр, чип, галка | компонент |
| конец | **Финал** | пилюля или число + заголовок акцентным шрифтом из блюра, 2–3,5 с | объект |

### 2.3 Пульс (замерено по разнице кадров)

- **~1 событие в секунду.** Медиана движения 0,45–0,55 с, медиана паузы 0,35–0,4 с, 75% пауз короче 0,9 с.
- **Контраст скорости** — главное, что отличает референсы от «плоского» моушена. Переходы-щелчки идут за 3–6 кадров (ирис 0,13–0,2 с, полный кадр → пилюля 0,13 с, снап-зум 2–4 кадра), а чтение держится 0,8–1,2 с. Средних «всё по 0,5 с» не бывает.
- Самая длинная пауза в ролике — финал (2–3,5 с). В середине пауза больше 1,5 с бывает только на 3D-мире.
- Вдох перед действием 0,3–0,4 с. Объект в это время не замирает, а плывёт.
- Большие удары (смена мира, награда) — на бит музыки (`beats.py`, §7.3).

### 2.4 Фон как ритм

- Главы чередуют **светлый** (`#F5F5F7`/белый — меню, карточки), **тёмный** (`#111113` — поиск, статусы, числа, часы) и **цветной** мир (оранжевый градиент, цвет фичи, 3D-сцена).
- **Фон меняется только под движением**: за 0,2–0,35 с, пока что-то едет или смазано. Например, карусель уезжает влево, а фон белый → серый → чёрный за 0,33 с. Затемнение «в чёрное и обратно» запрещено.
- Тоггл или успех **подкрашивает** фон в тон акцента (белый → тёплый `#FFF0E3`, белый → лавандовый у додокоинов) за 3–4 кадра.

### 2.5 Что в кадре
- **Один курсор на весь ролик.** Рука переезжает от тапа к тапу и уходит, когда действий нет дольше ~1 с. Новая рука на каждый тап даёт по два курсора в кадре.
- **Шиты**: нижние (внутри телефона) выезжают снизу и уезжают шторкой вниз — всегда вместе с контентом. Шит поверх телефона может вырасти из кнопки, но тоже уже с контентом, а закрывается шторкой вниз.
- **Бабл персонажа** появляется «мыслью»: сначала маленькая белая точка, потом побольше, потом сам бабл попом. Бабл всегда выше аватара по слоям.
- **Гироскоп** = физический наклон телефона (rotateY/X в 2–3 жеста), а аватар внутри догоняет с запаздыванием и лёгким перелётом. Не синусоида.
- Перемещения элемента «в сторону» показывай движением по дуге поверх соседей — если он проходит под аватаром, выглядит как «исчез и появился».
- **Интро ≥ 3 с** — зритель успевает понять, что это за экран.
- **Телефон ничем не перекрыт**: баблы, шиты и карточки не залезают на ключевой UI; если нужно место — уменьши телефон или сдвинь камеру, а не перекрывай.
- **Без лишних зумов**: если блок и так читается (акции, промо), не наезжай на него ради движения.
- Карусели и ленты двигаются **внутри своего фрейма** (clip), не вылезая за телефон.
- После нижних блоков (миссии, баннер внизу экрана) **поднимай телефон**, чтобы низ экрана был в кадре.
- **Видео внутри UI**: стоп-кадр видео передаётся в иконку/плитку через `handoff` (видео останавливается → кадр летит), без скачка «видео → статичная картинка».
- Объекты, которые «приземляются» (домик, иконки), падают сверху с лёгкой пружиной, а не появляются в центре.
- Иконки статусов из Figma не анимировать, если в макете они статичны; кольцо прогресса — по референсу (сегменты → галка), и всегда по центру своей плитки.
- Сердечки, конфетти от тапа — **локально у пальца**, по одному всплеску на тап.
- Плюс/кнопки, которые прячутся, — fade out/in, а не пропадают кадром.
- Проверяй обрезку глифов: высокие буквы (Ь, Й, Ё) и подстрочные не должны резаться `overflow`/`line-height` у текстовых блоков.
- Один герой. Всё, что за шторкой или поп-апом, — `blur(12–20px)`, `brightness(.55–.8)`, `scale .96`.
- Текст: только UI и максимум одна акцентная фраза или число (акцентный шрифт). Читаемый UI держится в кадре ≥ 1 с.
- Телефон-герой занимает 80–95% высоты и часто срезан краем. Наклонов почти нет.
- Поля безопасности 5%.

### 2.6 Если фич несколько (подборка, шоурил)

- Главы связывает **сквозной объект**: он переживает смену главы и меняет роль. Иконка → тост → иконка в шторке; линия маршрута → точка → нарисованная иконка → пилюля «Маршрут» → кнопка в телефоне; карточка статуса → плитка → кольцо → циферблат часов.
- Последний бит главы — **передача** вместо финала: выбери объект, который вылетит из экрана, свернётся или вырастет в следующую главу.
- В раскадровке у каждого стыка глав добавь колонку «что переходит в следующую главу». Если ничего — это склейка; таких не больше одной на 30 с.

## 4. Переходы (каталог)

Порядок предпочтения: **T1–T6 > T7–T11 > T12–T14**. Один и тот же тип не идёт два раза подряд. На ролик 60 с — минимум 6 разных типов.

| # | Переход | Как в референсах | Тайминг | Кит |
|---|---|---|---|---|
| **T1** | **Матч по форме / морф** | объект A стягивается в точку, B рождается из неё же: подарок → лента → цифра «0»; капля → иконка маршрута; иконка курьера → строка адреса | 0,3–0,4 с, нахлёст 2–4 кадра | `M.morph` |
| **T2** | **Контейнер из содержимого** | рамка вырастает вокруг того, что уже в кадре: иконка → тост; аватар → карточка профиля; тоггл → строка с описанием (растёт влево); кнопка → карточка статуса; кольцо → полный оранжевый кадр | 0,3–0,5 с `m.arrive` | `M.grow` |
| **T3** | **Схлопывание в содержимое** | полный фиолетовый кадр с «+192» → пилюля; карточка статуса → плитка с кольцом; видео → круг-аватар (ирис) | **3–6 кадров** `m.snap` | `M.collapse`, `M.iris` |
| **T4** | **Телефон собирается вокруг** | пилюля «Маршрут» висит, телефон поднимается **за** ней и она оказывается его кнопкой; или рамка телефона проявляется вокруг карточки | 0,4–0,6 с | `M.rise` / `M.frameIn` + `M.handoff` |
| **T5** | **Перелёт элемента** (shared element) | карточка, пилюля или бейдж летит из центра кадра в свой слот в телефоне (+192 → бейдж в шапке) | 0,5–0,6 с `m.move` | `M.handoff` |
| **T6** | **Выход из экрана** | элемент выпрыгивает из телефона к зрителю, телефон за ним размывается и темнеет (карточка «Приняли», ряд чипов); ингредиенты вылетают из сетки и становятся 3D | 0,3–0,45 с | `M.liftOut`, `M.burst` |
| **T7** | **Нырок в экран** | камера наезжает в телефон, рамка уходит за кадр, баннер становится героем; обратный — отъезд из экрана | 0,4–0,7 с | `M.cam` |
| **T8** | **Смена устройства вокруг элемента** | кольцо статуса из телефона остаётся в кадре, вокруг него появляется Apple Watch | 0,2–0,3 с | `M.grow` / `M.frameIn` |
| **T9** | **Флип глифа** | иконка разворачивается ребром по Y, с обратной стороны — другая (вилка и нож → курьер) | 0,13–0,3 с через ребро | `M.flip` |
| **T10** | **Смена телефона** | старый уходит вниз, новый поднимается, фон меняет цвет на нахлёсте | 0,5 с, нахлёст 0,15 с | `M.swap` |
| **T11** | **Скролл-вип → иконка** | лента скроллится с вертикальным смазом, телефон проваливается вниз, на его месте поп иконки следующей главы | 0,6 с | `M.scrollWhip` + `M.pop` |
| **T12** | **Смаз-вайп** | мягкая полоса акцентного цвета проходит через кадр, под ней меняется таб или баннер | 0,8–1,0 с | `M.smear` |
| **T13** | **Виппан** | горизонтальный уход с сильным блюром, приход с `m.arrive`; смена баннера — 4 кадра | 0,13–0,45 с | `M.whip` |
| **T14** | **Вспышка / жёсткая склейка на бит** | только между мирами (UI ↔ 3D) | 0,12 + 0,4 с | `M.flash` |

**Как выбрать переход**

| Из → в | Бери |
|---|---|
| объект → компонент | T2 (иконка → пилюля/тост) или T1 |
| компонент → экран | T4 (телефон за компонентом) или T5 |
| экран → компонент | T6 (выход из экрана) или T7 (нырок) |
| компонент → объект/число | T3 (схлопывание) или T1 |
| экран → экран | T10 или T13; внутри одного экрана — T12 |
| экран → мир (3D) | T7 нырок в баннер или T14 |
| мир → объект | T1 через зерно (цвет из мира становится точкой) |
| объект → объект | T9 или T1 |

## 6. Кадр, цвет, шрифты, звук

- **Цвет:** нейтральный кадр (`#F5F5F7`, белый, `#111113`) + **один акцент из UI фичи** (`--accent`, по умолчанию `#FF6900`). Оранжевый мир — вертикальный градиент `#FC771B → #E14F01`. Конфетти разноцветное, частицы — цвета акцента.
- **Шрифты:** UI — SF Pro (если есть файлы, иначе Inter, предупредить), акценты (числа, слоганы, финал) — акцентный шрифт бренда из файла пользователя, одно начертание, без fake-bold.
- **Тени:** мягкие и большие: `--card-shadow`; у поднятого элемента `--lift-shadow`.
- **Звук:** у каждого действия свой SFX — мягкие «интерфейсные» звуки (клик стекла, bloop, короткий шорох), никаких бластеров и «игровых» эффектов; разрыв купона — короткий бумажный rip ≤ 0,25 с. Кит сам ставит метки: `tap`, `pop`, `type`, `whoosh`, `swoosh`, `coins`, `riser`, `success`, `hit`, `tear`. Музыка — фанк, хип-хоп или грув на 99–120 BPM; громкость музыки под SFX ~0,6.

## 7. Процесс

1. **Бриф** (§1). Формат спросить обязательно.
2. **Раскадровка** — таблица `t | ступень | герой | микро/действие | переход | фон | звук`. Проверь по ней: типы переходов не повторяются подряд, фон чередуется, пульс около 1 события в секунду. Пришли пользователю. Если он не ответил, бери свою версию и иди дальше.
3. **Ассеты сразу в финальном качестве** (§1: ×4 / ×6 / видео в исходнике). Перевыгружать в конце дороже, чем сразу.
4. **Сборка** `work/scene.html` по скелету (§9) на `M.tl`.
5. **Превью** `--scale 0.5 --mblur 1` или 1080p `--scale 1 --mblur 4`. Контакт-лист (§10), просмотри сам, исправь. Минимум одна итерация до показа.
6. **Отправь превью** (SendUserFile), собери правки. Правки пользователь обычно даёт списком по кадрам — делай все пункты и отчитывайся по номерам.
7. **Музыка** (если есть): `beats.py` → `warp.py` (§7.3), превью с музыкой в 1080p.
8. **Финал в 4K** (§7.2–7.4): `density.cjs` → `render4k.sh` → `mix.py`. Отдать 4K-мастер и 1080p, сделанную из 4K (§7.5).

### 7.2 Качество: финал всегда 4K
- **Проверка плотности до рендера:** `node kit/density.cjs work/scene.html` — для каждой картинки максимальный экранный размер за весь ролик ÷ размер файла (в 4K). `✗` (k > 1,3) — переэкспортировать крупнее; `~` (1,1–1,3) — терпимо; цель ≤ 1,1. Без этой проверки финал не запускать.
- **Рендер:** `bash kit/render4k.sh work/scene.html out 3` — 3840×2160, motion blur 3 сэмпла, crf 14, кусками по 3 с в 2 потока. Скорость ≈ 1 с ролика за 55–60 с работы → **60-секундный ролик ≈ 55–60 мин**. mblur 4–5 — плавнее на паузе, но +30–60% времени.
- **Звук и 1080p:** `python3 kit/mix.py out <cues.json> music.wav sfx NAME --music-gain 0.6` — склейка кусков, музыка + SFX по меткам, плюс 1080p из 4K-мастера (Lanczos, crf 14 — заметно чётче, чем рендер сразу в 1080p). `cues.json` берётся с полного прохода (превью 1080p пишет `<out>.cues.json`).
- **Проверка:** кадры на стыках кусков (t = 2,95 / 3,0 …), кропы 1:1 из второй половины (там обычно самые крупные зумы), `ffprobe` (3840×2160, длительность), `volumedetect` (звук есть, пик ≤ 0 dB).

### 7.3 Синхрон с музыкой
1. `python3 kit/beats.py music.wav --json music/beats.json` — темп и доли (librosa).
2. Обрежь трек под длину ролика с фейдом в конце: `ffmpeg -i track.wav -t <dur> -af "afade=t=out:st=<dur-1.6>:d=1.6" music/track_cut.wav`.
3. Выпиши моменты сцены, которые должны попасть в бит (тапы, разрыв, удары, смены мира, ключевые вжухи) и `python3 kit/warp.py music/beats.json music/warp.json <t1> <t2> … --half --dur <длина сцены>` — получится список пар «время сцены → время ролика», скорость каждого участка 0,82–1,22.
4. В самом конце сцены (после `M.done`) — перехват `__seek`, длительности и звуковых меток:
```js
const WP = /* содержимое warp.json */; const WI=WP.map(p=>p[0]), WO=WP.map(p=>p[1]);
const lerp=(xs,ys,v)=>{if(v<=xs[0])return ys[0]+(v-xs[0]);for(let i=1;i<xs.length;i++)if(v<=xs[i])return ys[i-1]+(v-xs[i-1])*(ys[i]-ys[i-1])/(xs[i]-xs[i-1]);const n=xs.length-1;return ys[n]+(v-xs[n]);};
window.__seek=t=>{M.tl.seek(Math.max(0,lerp(WO,WI,t)),false);};
window.__duration=lerp(WI,WO,window.__duration);
window.__cues=window.__cues.map(c=>({...c,at:+lerp(WI,WO,c.at).toFixed(3)}));
```
Тайминги сцены при этом не трогаются — правки дальше делаются в «времени сцены», warp пересчитывается.

### 7.4 Долгий рендер в облачной сессии
- **Облачный контейнер засыпает и перезапускается, когда ход заканчивается** (между сообщениями пользователя): фоновые `nohup`-процессы умирают, `uptime` показывает 0 мин. Поэтому долгий рендер **держи в пределах одного хода**: запусти `setsid nohup bash kit/render4k.sh work/scene.html out 3 >/dev/null 2>&1 &` и проверяй его циклом `sleep 540; ls out/s4k_*.mp4 | wc -l` (≤ 10 мин на вызов) до конца. `ScheduleWakeup` не спасает — к пробуждению процессы уже убиты.
- Куски по 3 с: после обрыва повторный запуск продолжит с первого недостающего.
- Не больше 2 параллельных рендеров в 4K (при 8 ГБ); 3 потока → `Target crashed` и перезапуск машины.
- Перед стартом коротко скажи пользователю, сколько займёт; если перезапуск случился — скажи честно и продолжай с готовых кусков.

### 7.5 Доставка больших файлов
- `SendUserFile` принимает до **30 МБ**: 1080p (~20–25 МБ) отправляется в чат, 4K-мастер (~55–60 МБ на минуту) — нет.
- 4K кладём на компьютер пользователя через `device_commit_files`. Подводный камень: **первый кусок MP4 (с заголовком) при передаче переписывается** (+несколько КБ, файл портится), поэтому:
```bash
split -b 12m -d final_4K.mp4 part_            # куски по 12 МБ
base64 -w0 part_00 > part_00.b64              # первый — в base64, остальные как есть
# device_commit_files: part_00.b64, part_01, part_02 … → в папку проекта с точкой в имени (.part_*)
# на устройстве (device_bash):  base64 -d .part_00.b64 > .part_00 && cat .part_00 .part_01 … > final_4K.mp4 && md5sum final_4K.mp4
```
  Сверить md5 с исходником. Служебные куски удалить нельзя без разрешения — перенеси в `_to_delete/` и скажи пользователю. 1080p > 12 МБ отправляй тем же способом, если нужна точная копия.
- Итог пользователю: где лежит 4K-файл (путь на его компьютере), 1080p — карточкой в чате.

## 8. API кита (`window.M`)

Правила сборки, на которых легко споткнуться:
- **Сначала загрузи картинки, потом строй таймлайн.** `rectAt`, `cam`, `grow`, `handoff` меряют элементы при сборке — у незагруженного `<img>` высота 0, и тапы, камера и перелёты промахиваются. Оберни сцену в `(async()=>{ await preload(...); …; M.done() })()` и ставь у каждого `<img>` явные `width` и `height` (из реальных размеров файла).
- В `fromTo` свойство, которое есть только во from (например `autoAlpha:1`), не анимируется — дублируй его в to.
- Всё, что должно быть скрыто до своего момента, прячь `gsap.set(..., {autoAlpha:0})` при сборке, а `fromTo` ставь с `immediateRender:false`, иначе стартовое состояние видно с первого кадра.

Только твины на `M.tl`. Без `setTimeout`, rAF, `Math.random` (бери `M.rng(seed)`), без CSS-transitions. Шрифты и картинки локальные. Элементы, которые летят через `handoff`, стилизуй **собственными классами** (не селекторами вида `.parent .child`), иначе клон для `handoff` потеряет стиль.

## 11. Ограничения (сказать честно)

- 3D (монеты, руки, домики, персонажи, города) кит не рендерит: нужны PNG или секвенции. Без них — 2D-заменители.
- Музыку не пишем; SFX-плейсхолдеры синтетические.
- Логотипы, персонажи, коллаб-ассеты, акцентный шрифт и SF Pro — только из файлов пользователя.
- Видео-футаж (город, самокат, стрим) нельзя вставлять тегом `<video>`, рендер станет недетерминированным. Только секвенцией: `ffmpeg -i in.mov -vf "fps=30,crop=W:H:X:Y" -q:v 2 f%03d.jpg` (JPEG без альфы, PNG — если нужна альфа после кеинга), **в исходном разрешении**; `<img>` + смена `src` по кадрам на таймлайне.
- Финал 60 с в 4K рендерится около часа; пользователя предупредить заранее.

#!/usr/bin/env node
/* Frame-accurate renderer: seeks the page's GSAP timeline per (sub)frame, screenshots, pipes to ffmpeg.
   Motion blur = N sub-frames averaged per output frame (like RSMB/AE shutter 180–360°).
   Usage:
     node render.cjs scene.html out.mp4 [--fps 30] [--scale 2] [--mblur 4] [--shutter 0.5]
                     [--from 0] [--to <sec>] [--music track.wav] [--sfx sfxDir] [--music-gain 0.8] [--crf 16]
   Preview: --scale 0.5 --mblur 1 (fast)    Final: --scale 2 --mblur 6 (4K, smooth blur)
   If the bundled Chromium does not match the playwright version: CHROMIUM_PATH=/path/to/chrome node render.cjs …                                 */
const {chromium} = require('playwright');
const {spawn, execFileSync} = require('child_process');
const fs = require('fs'), path = require('path');

const args = process.argv.slice(2), BOOL=new Set(['keep']), kv={}, pos=[];
for(let i=0;i<args.length;i++){ const a=args[i]; if(a.startsWith('--')){ const k=a.slice(2); if(BOOL.has(k)) kv[k]=true; else kv[k]=args[++i]; } else pos.push(a); }
const opt = (k,d)=> kv[k]!==undefined ? kv[k] : d;
const [input, output] = pos; if(!input||!output){console.error('usage: node render.cjs scene.html out.mp4 [opts]');process.exit(1);}
const fps=+opt('fps',30), scale=+opt('scale',1), mblur=Math.max(1,+opt('mblur',1)), shutter=+opt('shutter',0.5);
const crf=opt('crf','16'), music=opt('music',null), sfxDir=opt('sfx',null), musicGain=+opt('music-gain',0.8);

(async()=>{
  const browser = await chromium.launch({args:['--force-color-profile=srgb','--disable-lcd-text'], executablePath: process.env.CHROMIUM_PATH || undefined});
  const page = await browser.newPage({viewport:{width:1920,height:1080}, deviceScaleFactor:scale});
  page.on('console', m=>{ if(m.type()==='error') console.error('[page]', m.text()); });
  page.on('pageerror', e=>{console.error('[pageerror]', e.message); process.exit(2);});
  await page.goto('file://'+path.resolve(input));
  const {w,h} = await page.evaluate(()=>{const s=document.querySelector('#stage');return {w:s.offsetWidth,h:s.offsetHeight};});
  await page.setViewportSize({width:w,height:h});
  await page.waitForFunction('window.__ready===true',null,{timeout:30000});
  await page.evaluate(async()=>{await document.fonts.ready; await Promise.all([...document.images].map(i=>i.decode().catch(()=>{})));});
  const dur = await page.evaluate('window.__duration');
  const from=+opt('from',0), to=Math.min(+opt('to',dur), dur);
  const frames=Math.round((to-from)*fps);
  console.log(`stage ${w}x${h} @${scale}x → ${w*scale}x${h*scale}, ${frames} frames, mblur ${mblur}`);

  fs.mkdirSync(path.dirname(path.resolve(output)),{recursive:true});
  const tmp = output.replace(/\.mp4$/,'') + '.video.mp4';
  const vf = mblur>1 ? `tmix=frames=${mblur}:weights='${Array(mblur).fill(1).join(' ')}',select='not(mod(n+1\\,${mblur}))',setpts=N/${fps}/TB` : 'null';
  const ff = spawn('ffmpeg',['-v','error','-y','-f','image2pipe','-framerate',String(fps*mblur),'-i','-',
     '-vf',vf+',format=yuv420p','-r',String(fps),'-c:v','libx264','-preset','medium','-crf',crf,'-movflags','+faststart',tmp],{stdio:['pipe','inherit','inherit']});
  const t0=Date.now();
  for(let f=0; f<frames; f++){
    for(let s=0; s<mblur; s++){
      const t = from + (f + (mblur>1 ? (s/(mblur-1)-0.5)*shutter : 0))/fps;
      await page.evaluate(t=>window.__seek(Math.max(0,t)), t);
      const buf = await page.screenshot({type:'png', animations:'disabled', caret:'hide'});
      if(!ff.stdin.write(buf)) await new Promise(r=>ff.stdin.once('drain',r));
    }
    if(f%30===0) process.stdout.write(`\r${f}/${frames} (${((Date.now()-t0)/1000).toFixed(0)}s)`);
  }
  ff.stdin.end(); await new Promise(r=>ff.on('close',r));
  const cues = (await page.evaluate('window.__cues||[]')).filter(c=>c.at>=from && c.at<to);
  await browser.close(); console.log(`\nvideo done in ${((Date.now()-t0)/1000).toFixed(0)}s`);
  fs.writeFileSync(output.replace(/\.mp4$/,'')+'.cues.json', JSON.stringify(cues,null,1));

  // ── Audio: music bed + SFX cues ─────────────────────────────────────────
  const inputs=['-i',tmp]; const parts=[]; let n=1;
  if(music){ inputs.push('-i',music); parts.push(`[${n}:a]atrim=start=${from},asetpts=PTS-STARTPTS,volume=${musicGain}[m]`); n++; }
  const sfxLabels=[];
  if(sfxDir){ for(const c of cues){ const f=['wav','mp3','aif'].map(e=>path.join(sfxDir,`${c.name}.${e}`)).find(fs.existsSync); if(!f) continue;
      inputs.push('-i',f); const ms=Math.round((c.at-from)*1000); parts.push(`[${n}:a]adelay=${ms}|${ms},volume=${c.gain}[s${n}]`); sfxLabels.push(`[s${n}]`); n++; } }
  if(parts.length){
    const mixIn=(music?['[m]']:[]).concat(sfxLabels);
    const fc=parts.join(';')+`;${mixIn.join('')}amix=inputs=${mixIn.length}:normalize=0:duration=longest,alimiter=limit=0.95,apad,atrim=0:${(to-from).toFixed(3)}[a]`;
    execFileSync('ffmpeg',['-v','error','-y',...inputs,'-filter_complex',fc,'-map','0:v','-map','[a]','-c:v','copy','-c:a','aac','-b:a','256k','-t',(to-from).toFixed(3),output]);
    if(!kv.keep) fs.unlinkSync(tmp);
  } else fs.renameSync(tmp, output);
  console.log('→', output);
})().catch(e=>{console.error(e);process.exit(1);});

### kit/make_sfx.py

#!/usr/bin/env python3
"""Placeholder UI SFX pack (synthesised, soft 'iOS-like' interface sounds).
Replace files with studio SFX of the same names: tap, pop, type, whoosh, swoosh, coins, riser, success, hit, tear.
usage: python3 make_sfx.py out_dir"""
import numpy as np, wave, sys, os
from scipy.signal import butter, sosfilt
SR = 48000
rnd = np.random.default_rng(3)
out = sys.argv[1] if len(sys.argv) > 1 else 'sfx'; os.makedirs(out, exist_ok=True)
def t(d): return np.arange(int(SR*d))/SR
def bp(x, lo, hi, o=2): return sosfilt(butter(o, [lo, hi], 'band', fs=SR, output='sos'), x)
def lp(x, f, o=2): return sosfilt(butter(o, f, 'low', fs=SR, output='sos'), x)
def hp(x, f, o=2): return sosfilt(butter(o, f, 'high', fs=SR, output='sos'), x)
def env(n, a, d): e = np.exp(-np.arange(n)/SR/d); k = max(1, int(SR*a)); e[:k] *= np.linspace(0, 1, k); return e
def fade(x, ms=4): k = int(SR*ms/1000); x[-k:] *= np.linspace(1, 0, k); return x
def save(name, x, peak=0.7):
    x = fade(np.asarray(x, float)); x = x/(np.abs(x).max()+1e-9)*peak
    with wave.open(os.path.join(out, name+'.wav'), 'w') as w:
        w.setnchannels(1); w.setsampwidth(2); w.setframerate(SR); w.writeframes((np.clip(x, -1, 1)*32767).astype(np.int16).tobytes())

# tap — soft glassy click: very short band-passed transient + tiny low body (no pitch sweep)
T = t(0.06); n = len(T)
click = bp(rnd.normal(size=n), 2500, 7000)*env(n, .0003, .0025)
body = np.sin(2*np.pi*190*T)*env(n, .001, .012)*.5
save('tap', click*.9 + body, .45)
# pop — gentle "bloop": short sine with a small upward glide, rounded attack, warm
T = t(0.12); n = len(T); f = 520 + 160*(1-np.exp(-T/0.02))
ph = 2*np.pi*np.cumsum(f)/SR
x = (np.sin(ph) + .18*np.sin(2*ph))*env(n, .004, .035)
save('pop', lp(x, 3500), .38)
# type — key tick
T = t(0.03); n = len(T); save('type', bp(rnd.normal(size=n), 3000, 8000)*env(n, .0002, .003), .25)
# whoosh — airy band-passed noise swell
T = t(0.5); n = len(T); sh = np.sin(np.pi*T/T[-1])**2
x = np.zeros(n); seg = 2048
for i in range(0, n, seg):
    fc = 500 + 2200*(i/n); x[i:i+seg] = bp(rnd.normal(size=min(seg, n-i)+0), fc*.6, fc*1.6)[:min(seg, n-i)]
save('whoosh', lp(x*sh, 6000), .35)
T = t(0.26); n = len(T); sh = np.sin(np.pi*T/T[-1])**2
save('swoosh', bp(rnd.normal(size=n), 1200, 6000)*sh, .22)
# coins — light chimes
T = t(1.0); x = np.zeros(len(T))
for i in range(18):
    s = int(rnd.uniform(0, .75)*SR); tt = t(.18); fr = rnd.uniform(2600, 4600)
    seg = (np.sin(2*np.pi*fr*tt) + .35*np.sin(2*np.pi*fr*2.41*tt))*env(len(tt), .001, .05)*rnd.uniform(.3, 1)
    x[s:s+len(seg)] += seg[:len(x)-s]
save('coins', x, .35)
# riser — soft tonal swell
T = t(0.7); f = 400 + 500*(T/T[-1]); save('riser', np.sin(2*np.pi*np.cumsum(f)/SR)*(T/T[-1])**2*env(len(T), .0, 10), .2)
# success — two soft marimba-ish notes
T = t(0.6); x = np.zeros(len(T))
for fr, d in [(880, 0), (1318.5, .09)]:
    k = int(d*SR); tt = T[:len(T)-k]
    x[k:] += (np.sin(2*np.pi*fr*tt) + .25*np.sin(2*np.pi*fr*4*tt))*env(len(tt), .002, .12)
save('success', x, .35)
# hit — soft low thud
T = t(0.35); f = 70 + 60*np.exp(-T/0.03); save('hit', lp(np.sin(2*np.pi*np.cumsum(f)/SR)*env(len(T), .002, .09), 800), .5)
# tear — short paper rip: crackle of tiny filtered impulses over a noisy bed, ~0.22 s
T = t(0.24); n = len(T); x = np.zeros(n)
grains = np.sort(rnd.uniform(0, .19, 70))
for g in grains:
    s = int(g*SR); L = int(SR*.004); gg = rnd.normal(size=L)*np.exp(-np.arange(L)/SR/.0008)*rnd.uniform(.4, 1)
    x[s:s+L] += gg[:n-s]
bed = rnd.normal(size=n)*np.clip(np.sin(np.pi*np.clip(T/.2, 0, 1)), 0, 1)*.25
x = hp(bp(x + bed, 1500, 9000), 900)
save('tear', x*env(n, .002, .12), .5)
print('sfx →', out, sorted(os.listdir(out)))

a = sys.argv[1:]; half = '--half' in a
dur = float(a[a.index('--dur')+1]) if '--dur' in a else None
nums = [float(x) for i, x in enumerate(a[2:]) if not x.startswith('--') and (i == 0 or a[2+i-1] != '--dur')]

if dur: ps, po = pts[-1]; pts.append((dur, po + (dur-ps)))
